# План улучшения «Бамбуль: хозяин едет»

Статус: черновик на согласование. Код не менялся. Дальше добавим ваши пожелания.

## 1. Что есть сейчас (по факту проверки)

- Браузерная 2.5D-игра на чистом JS, без сборки (~1 МБ кода, 5 комнат, 46 коммитов), ассеты ~21 МБ (озвучка 13 МБ).
- Запускается, главное меню и гостиная рендерятся корректно (скриншот снят).
- Тесты, запущенные мной: `test_story` 43/43, `dlg_selftest` 1930/1932 (2 падения: очередь реплик после истечения текущей; гигиена текста, пример «Диван, не сейчас. Я сказал, не сейчас! ...Ладно»). `test_ui` падает по таймауту на кнопке `rNo` (диалог «Продолжить?»), хотя `PROJECT_STATUS.md` считает это артефактом теста.
- Не проверено никем: FPS на реальном GPU/Android, живая озвучка на слух, touch на устройстве.

## 2. Найденные проблемы

| # | Проблема | Почему важно |
|---|---|---|
| P1 | Нет проверки на реальном телефоне и GPU; в QA только software-render (35–90 мс/кадр) | Целевая платформа — Android, цифр нет |
| P2 | Шрифты с Google Fonts в `index.html`; озвучка не работает с `file://` | Заявлено «без сети», но зависит от сети и от сервера |
| P3 | Тесты не в CI, запуск вручную, пути захардкожены (`/opt/node22/...`); нет `package.json` | Регрессии ловятся только руками |
| P4 | Падающие тесты (см. выше) и расхождение «отчёт ≠ факт» | Нельзя понять, что реально сломано |
| P5 | Два набора героя (painted/toon), Dan и лендлорд в другом стиле, `legacy/`, `assets/char/orig`, `src`, `toon` | Лишний вес, рассинхрон стиля |
| P6 | Вес: 21 МБ, озвучка 1001 клип грузится по требованию? (проверить), нет прогресса загрузки по ассетам | Долгая первая загрузка на мобильном интернете |
| P7 | Глобальный `BB`, файлы по 800–1600 строк (`dialogue.js`, `minigames.js`, `work.js`) | Тяжело расширять |
| P8 | Нет PWA/офлайна, нет версии сохранений, один слот `localStorage` | Для телефона хотелось бы «установить» игру |
| P9 | Нет аналитики баланса: сложность/таймер подбирались без прогонов | Возможны непроходимые или слишком лёгкие прохождения |
| P10 | Нет локализации/субтитров-настроек, доступности (размер текста, контраст, режим без мата) | Ограничивает аудиторию |

## 3. План по этапам

**Этап 0 — Фундамент (1–2 дня)**
- `package.json`, один `npm test`, скрипты без захардкоженных путей, CI (GitHub Actions) с Playwright.
- Починить 2 падения dialogue и `test_ui`; привести `QA_REPORT.md` в соответствие с реальностью.
- Локальные шрифты вместо Google Fonts.

**Этап 1 — Надёжность и производительность (2–4 дня)**
- Замер FPS на реальном Android и ПК с GPU; бюджет: 60 fps ПК, 30+ мобильный.
- Ленивая загрузка озвучки и текстур, прогресс-бар по реальным ассетам, сжатие (webp/ogg).
- Версионирование сохранений, миграции, несколько слотов.
- Service worker: офлайн и установка как приложение.

**Этап 2 — Геймплей и баланс (3–5 дней)**
- Бот-прогон: автотест, проходящий игру разными стратегиями, чтобы проверить время, концовки и невозможные состояния.
- Подстройка таймера и сложности (лёгкий/обычный/«хаос»).
- Аудит всех 7 мини-игр на повторяемость и понятность подсказок; обучение без стен текста.

**Этап 3 — Контент и стиль (по желанию)**
- Единый стиль Dan/хозяина с героем; чистка лишних ассетов.
- Новые комнаты/события/концовки, больше реакций на действия игрока.
- Музыка/эмбиент (сейчас музыки нет).

**Этап 4 — Рефакторинг (параллельно)**
- Разбить крупные файлы, сузить глобальный `BB` до явных модулей, не ломая «без сборки» (или ввести лёгкую сборку, если решите).

**Этап 5 — Доступность и релиз**
- Настройки: размер текста, контраст, цензура мата, управление.
- Публикация (GitHub Pages / itch.io), README со скриншотами и инструкцией запуска.
